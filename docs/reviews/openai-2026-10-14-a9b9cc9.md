Major, app/controllers/drawio_controller.rb:15
Problem: POST /drawio/token returns 200 with an empty token when two-factor activation is pending (ApiToken.issue returns ''), instead of refusing the request. The UI then proceeds to save with an empty header, causing a later 401/403 from the REST API and a generic “saving failed” alert with no clear reason. It also makes the behavior dependent on later requests rather than failing early.
Failure scenario: A user with must_activate_twofa? true opens a wiki page, double-clicks a diagram, and clicks Save. The browser posts to /drawio/token, receives {token: ""} with 200 and no-store, then attempts the REST calls with X-Redmine-Drawio-Token: "" and gets 401/403. The user sees a generic error and the diagram is lost, the endpoint never indicated that saving is impossible due to 2FA.
Fix: After computing token = RedmineDrawio::ApiToken.issue(User.current), return head :forbidden (or render 403 JSON with no body) if token.blank?. Example:
  def token
    response.headers['Cache-Control'] = 'no-store'
    t = RedmineDrawio::ApiToken.issue(User.current)
    return head :forbidden if t.blank?
    render json: { token: t }
  end
Also add an integration test that simulates a 2FA-pending user (e.g., stubbing User#must_activate_twofa? to return true for the logged-in user) and asserts POST /drawio/token responds 403 and no "token" key in the body.
