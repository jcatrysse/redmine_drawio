Minor, test/integration/drawio_token_test.rb:146-154
- Problem: The new test “no token while two-factor activation is pending” posts with Accept: application/json, which makes Redmine treat the request as an API request (ignoring the login session). That can cause 401/403 due to anonymous API access regardless of two-factor state. As a result, the test may pass without actually exercising the intended scenario (logged-in session + valid CSRF + 2FA activation pending). It also accepts a wide status range [302, 401, 403], further weakening the assertion.
- Concrete failure scenario: If Redmine changes its Accept handling or if the two-factor gate in RedmineDrawio::ApiToken.issue is accidentally removed, the endpoint could still return 401/403 in API mode (because the session is ignored), and the test would continue to pass even though 2FA-pending users would incorrectly receive a token in the normal (HTML + CSRF) path.
- Fix: Drive the session-authenticated, CSRF-protected HTML path and assert the exact 403. For example:
  - Do not set Accept: application/json (let it default to HTML).
  - Include a valid CSRF token (reuse the helper/mechanism used in the “200 with CSRF” test in the same file).
  - Stub must_activate_twofa? to true as done now.
  - Assert response.status == 403 and response.body.blank? (or at least that it does not contain '"token"').

Resolution: partly right, fixed in the next commit.
